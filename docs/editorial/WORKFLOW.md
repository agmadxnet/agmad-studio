# Development note → article → video

1. Capture a development note for meaningful work: problem, changed files/version, experiment, actual result, failure, evidence and untested areas.
2. Choose notes that help someone complete a real task. Daily capture does not require daily publication.
3. Draft an English article and Arabic counterpart: task, requirements, steps, synthetic example, limitations, related tool and source reference.
4. Verify claims against the exact tool version. Keep existing article URLs/IDs and original publication dates; update the modified date for substantive revisions.
5. Review screenshots and examples for sensitive data/copyright. Separate observed results from proposed work.
6. Publish through the existing WordPress workflow only after review. This repository has no automatic publishing workflow.
7. Derive the video outline from the reviewed article: problem, short demonstration, result, caveat, link to the canonical article/tool.
8. Include useful published work in an occasional newsletter, with confirmed consent and unsubscribe; no automatic daily send.

Editorial queues, commercial plans and internal delivery schedules are maintained privately. Public notes should describe verified work and its limitations.
